# 검증 기록 — 분류기를 믿어도 되는가

> 한 줄 요약: README의 결과표와 '진단 과정 7단계'를 실험 기록 형식(가설 → 스크립트 → 결과 수치 → 결론)으로 다시 적은 것이다. 수치는 README에 있는 것만 옮겼고 새로 만든 것은 없다. 실측 수치는 WM-811K 원본(LSWMD.pkl, 약 2GB)으로 낸 것이라 이 저장소의 CI나 데이터 없는 환경에서는 재측정하지 않는다(재현 근거는 `results/`). 날짜는 적지 않는다 — 기록의 순서가 곧 실험 순서다.

공통 조건: 결함 라벨 8종 25,519장 / 로트 8,047개(저장소 자체 계산) / 맵 크기 329종. 분할은 **로트 단위**(`lotName`으로 group split; 같은 로트의 웨이퍼는 패턴을 공유하므로 무작위 분할은 누수). 지표는 **macro-F1, 결함 8종 고정**(EDGE_RING 9,680 vs NEAR_FULL 149, 65배 불균형이라 accuracy 무의미; 예측에만 등장한 CLEAN을 라벨 집합에 넣으면 F1 0인 9번째 클래스가 평균을 끌어내리므로 모든 스크립트가 같은 8종으로 계산). 최종 숫자는 시드 5개 반복의 평균 ± 표준편차.

## 실험 0 — 합성 자체 검증

- **가설**: 생성기와 분류기가 같은 규칙을 공유하므로 합성 데이터에서 분류기는 맞아야 한다. 틀리면 코딩 오류다.
- **스크립트**: `python wafer_pattern_classifier.py` (noise 0 / 0.03 각각, 실패 시 종료 코드 1)
- **결과**: 7/7 일치. clean 웨이퍼에 noise를 주면 뒤집힌 다이 비율이 CLEAN 임계값 2% 근처에서 흔들리므로 CLEAN과 RANDOM을 모두 정답으로 인정한다. 균일 무작위 불량의 평균 반경(약 0.67)이 엣지 임계값 0.70에 붙어 있어 소수 불량 웨이퍼가 EDGE_LOC로 새는 경우가 있다.
- **결론**: 합성의 7/7은 성능이 아니라 코딩 오류 확인이다. 미교정 규칙이 노이즈에 약하다는 것을 합성에서도 볼 수 있어 그대로 두었다. 이 원칙(합성 데이터의 역할 제한)은 이후 모든 실험과 `tests/`, `--demo`에 그대로 적용된다.

## 실험 1 — 미교정 규칙의 실측 평가: 0.167의 원인

- **가설**: 합성 기준 임계값을 실측에 그대로 적용하면 떨어질 것이다. 떨어진다면 특징이 없어서인가, 임계값이 틀려서인가.
- **스크립트**: `python wm811k_evaluate.py` (미교정 규칙, 클래스별 특징 분포와 단일 특징 AUC)
- **결과**: macro-F1 0.167. 특징별 단일 AUC: EDGE_RING은 r_mean 0.956, NEAR_FULL은 fail_frac 1.000, CENTER는 r_std 0.966.
- **결론**: 신호는 있었다. 원인은 특징 부재가 아니라 노이즈 없는 합성 데이터에서 정한 임계값이다. 실측은 패턴 위에 산발적 불량이 깔려 있어 모든 반경 통계가 바깥으로 밀린다.

## 실험 2 — 임계값 교정 (train 로트에서만)

- **가설**: 임계값을 실측 분포에 맞추면 규칙 구조 그대로도 크게 오른다. 교정은 train에서만 해야 test가 낙관 편향되지 않는다.
- **스크립트**: `python wm811k_calibrate.py` (train 로트에서 임계값 좌표 하강, test는 최종 1회)
- **결과**: 0.167 → 0.558 (+0.373). `center_r` 0.30 → 0.74, `ring_std` 0.15 → 0.24. 구조적 특징 11개를 줘도 규칙 구조는 0.625(+0.07)에 그친다.
- **결론**: 임계값 이동 폭이 곧 합성과 실측의 거리다. 교정만으로는 규칙 구조의 상한이 낮다.

## 실험 3 — 같은 특징의 트리와 비교

- **가설**: 임계값을 교정하는 순간 손으로 트리를 적합하는 것이므로, 실제 트리보다 나은지 확인해야 한다.
- **스크립트**: `python wm811k_calibrate.py` (결정트리 깊이는 train 내부 GroupKFold로 선택, 랜덤포레스트 기준선)
- **결과**: 전역 6개로 결정트리 0.710, 랜덤포레스트 0.765 — 교정 규칙 0.558보다 +0.227 높다. 트리 구조를 보면 `r_std > 0.27 & axial_c ≤ 0.17 → CENTER` 경로로 반경을 보지 않고 CENTER에 도달한다.
- **결론**: 순서 의존적 if-else 규칙은 이런 대안 경로를 표현할 수 없다. 수작업 규칙의 가치는 성능이 아니라 해석 가능성으로 좁혀진다.

## 실험 4 — SCRATCH의 한계: 전역 통계의 표현력

- **가설**: 트리로도 못 잡는 클래스가 있다면 특징 쪽 문제다.
- **스크립트**: `wm811k_calibrate.py` 결과의 클래스별 F1, `wm811k_evaluate.py`의 AUC
- **결과**: SCRATCH는 트리로도 F1 0.319. 축 집중도(axial_c) AUC 0.682뿐.
- **결론**: 얇은 연결된 선은 전역 요약 통계로 표현되지 않는다. 연결 성분 기반 특징이 필요하다.

## 실험 5 — 구조적 특징 11개 추가

- **가설**: 각 특징이 어떤 클래스를 겨냥하는지 설계 단계에서 정하고 AUC로 검증하면, 어느 특징이 어느 물리 현상을 재는지 추적할 수 있다.
- **스크립트**: `python wm811k_structural.py` (연결 성분, 각도 커버리지, 반경 프로파일)
- **결과**: RF 0.765 → 0.878. 겨냥 대비 AUC: 최내측 반경 구간 불량률(prof0) → CENTER 0.990, 중간 구간(prof2) → DONUT 0.980, 최대 성분 세장비(elongation) → SCRATCH 0.930, 외곽 각도 커버리지 → EDGE_RING 0.808. SCRATCH F1 0.325 → 0.765. **설계 가정 하나는 틀렸다**: RANDOM을 "작은 성분 수십 개"로 예상했으나 실측은 불량 밀도가 높아 성분이 오히려 적고 컸다(n_comp AUC 0.155). 교정이 해당 규칙을 무효화(격자에 넣어둔 무효값 선택)했다.
- **결론**: 특징 추가의 효과는 설계 의도와 AUC로 각각 확인한다. 틀린 가정은 기록하고 교정이 걸러내게 둔다.

## 실험 6 — 남은 혼동(EDGE_LOC↔LOC) 겨냥 위치 특징 3개 + 반복 검증

- **가설**: 남은 오류의 절반인 EDGE_LOC↔LOC 혼동(256장)은 "최대 성분이 어디 있는가"로 갈린다. 그리고 단일 분할 수치는 재현되는가.
- **스크립트**: `python wm811k_validate.py` (로트 분할 시드 5개, 같은 5분할에서 짝지어 비교)
- **결과**: 0.878 → 0.907 ± 0.008. 최대 연결 성분의 무게중심 반경(big_r, AUC 0.846)과 최내측 반경(big_r_min, 0.807)이 효과. 각도 폭(big_span)은 AUC 0.520으로 무용 — "엣지 국소는 호(弧)라 넓다"는 직관이 틀렸고 두 클래스의 각도 폭은 같았다(54° vs 52°). 5개 분할 모두 개선, Δ +0.030이 분할 간 표준편차 0.008의 4배. SCRATCH도 +0.083 올랐는데 겨냥한 것이 아니었다 — 스크래치는 중심을 지나 무게중심이 안쪽이라 big_r이 LOC과의 혼동을 줄였다. 단일 분할(시드 42)은 0.890 → 0.919였다.
- **결론**: 반복 검증 없이 보고했다면 최고치(0.919)를 대표값으로 쓸 뻔했다. 채택 기준을 "5회 모두 개선이고 Δ 평균이 분할 간 표준편차보다 클 것"으로 고정했다.

## 실험 7 — RF 규제

- **가설**: train/test 격차(0.99/0.91)를 min_samples_leaf로 줄일 수 있는가. 줄이는 것이 목표인가.
- **스크립트**: `python wm811k_validate.py` (leaf는 train 내부 GroupKFold로 선택)
- **결과**: 선택값 leaf = 2. leaf를 키우면 train/test 격차가 0.074 → 0.014로 줄지만 test도 0.919 → 0.887로 같이 떨어진다.
- **결론**: 격차 축소가 목표가 아니므로 leaf = 2 유지. 보고할 때 train/test를 둘 다 적는다.

## 실험 8 (미측정) — 강건 특징 8개 + 그래디언트 부스팅

- **가설**: 남은 오류(LOC→EDGE_LOC 5회 합산 542장, SCRATCH→LOC 270장)는 노이즈 수준을 재던 성분 특징을 "크기 ≥ 3 성분" 기준으로 바꾸면 줄어든다. 모델을 RF에서 HGB로 바꾸면 얼마나 오르는지는 특징의 기여와 분리해 본다.
- **스크립트**: `python wm811k_improve.py` (RF-20 / RF-28 / HGB-20 / HGB-28, 같은 5분할에서 짝지어)
- **특징**: `isolated_frac`, `sig_frac`, `n_comp_sig`(고립 다이와 크기 3 이상 성분 분리), `fail_nb_mean`(불량 다이당 8-이웃 불량 수), `big_extent`, `big_len`(선과 덩어리), `big_edge_touch`(EDGE_LOC↔LOC 직접 겨냥), `second_frac`.
- **결과**: **실측 미측정.** 합성 WM-811K 형식 데이터로 파이프라인 전체(prepare → evaluate → calibrate → structural → validate → improve)가 끝까지 도는 것만 확인했고 합성에서의 F1은 성능이 아니다. 예상 실행 시간(4코어 기준, 추정): 특징 추출 ~2분, RF/HGB 10회 ~5분.
- **결론(예정)**: 채택 기준은 실험 6과 같다. 결과가 개선이 아니면 "채택 기준에 못 미쳐 기각"으로 적는다. 이 실험이 끝나면 `docs/defect_signatures.md`가 가설로 인용하는 `big_edge_touch`·`isolated_frac` 문장을 측정값으로 바꾼다.

## 한계 (README와 같음)

- 남은 오류의 대부분은 LOC → EDGE_LOC(5회 합산 542장)과 SCRATCH → LOC(270장). 둘 다 "국소 덩어리가 어디 있는가"의 경계 문제다.
- WM-811K는 맵 크기가 329종이고 실제 mm 크기를 알 수 없다. 모든 반경 통계는 비율이다.
- 랜덤포레스트의 train/test 격차(0.99/0.91)가 남아 있다.
- `none`(정상) 147,431장은 제외했다. 실제 배치에서는 "패턴이 있는가"를 먼저 판단해야 하며 그 단계가 더 어렵다(`wm811k_evaluate.py --with-none` 경로는 있으나 결과 미측정 — [`roadmap.md`](roadmap.md)).
- CNN 등 이미지 기반 방법은 시도하지 않았다. 해석 가능한 특징 20개로 0.91에 도달하는 것이 관심이었다.
- 결함 부분집합은 로트당 평균 3.2장(25,519 / 8,047)이라 로트 내 반복·방위각·슬롯 분석은 대부분 로트에서 n이 부족하다.

## 수치 불변 규칙

특징값·분할·모델에 영향을 주는 변경 — `wafer_map_visualizer.wafermap_to_df`, `wafer_pattern_classifier.classify_wafer_pattern`의 규칙·임계값 상수, `wm811k_structural.structural_features`, `wm811k_validate.largest_component_features / lot_split / make_rf`, `wm811k_improve.robust_features / make_hgb`, `wm811k_calibrate`의 규칙·격자, `CLASSES` 순서 — 는 **`results/`를 실데이터로 다시 만들어 README 수치와 같은 커밋에서 갱신할 때만** 한다. 그 전까지는 주석 한 줄도 넣지 않는다.

`tests/test_features_snapshot.py`가 합성 고정 맵 3장의 특징값 28개를 소수 6자리로 고정해 두어, 리팩터가 값을 바꾸면 CI가 알린다. 이 테스트가 깨졌다면 (1) 생성기가 바뀐 것인지(맵 해시 단언이 먼저 깨진다) (2) 특징 코드가 바뀐 것인지 구분한 뒤, 후자라면 README 수치를 다시 재야 한다. 스냅샷 값을 고쳐서 통과시키는 것은 답이 아니다.

실측 수치를 낸 환경(Python·패키지 버전)은 `results/environment.txt`의 `[measured]` 블록에 소유자가 기록한다. 현재는 미기록이다.
