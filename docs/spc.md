# 분류 위의 SPC — `wm811k_spc.py` 상세

> 한 줄 요약: 웨이퍼 한 장의 판정은 분류기가 하고, 이 스크립트는 그 위 단계다. 판정 결과를 시간 순서로 부분군에 묶어 "이 패턴의 발생률이 평소보다 늘고 있는가"를 관리도로 보고, 상승 알람이 난 패턴에 TEL 모듈 기준 점검 항목과 대조할 장비 측 로그를 붙인다. 한 장씩은 정상인데 방향이 한쪽으로 기우는 것(소모품 마모, 챔버 오염 축적)을 잡는 것이 목적이다. 이 문서의 데모 수치는 전부 합성이며 **로직 확인이지 탐지 성능이 아니다.**

업계 용어로 옮기면: 패턴별 p 관리도 = FDC(fault detection and classification)의 fault detection 지표를 장비 센서가 아니라 결과(웨이퍼 맵) 쪽에서 만든 것, Phase I / II = 한계 설정(limit setting) / 감시(monitoring), EWMA = run-to-run 드리프트 감시, 저신뢰 관리도 = 모델 드리프트(model drift) 감시. SEMI E10 관점에서 상승 알람은 "그대로 두면 비예정 정지(unscheduled downtime)가 될 사건을 예정 정지(scheduled downtime, PM 앞당기기·부품 선수배)로 바꾸는 신호"다. 장비 쪽 FDC/APC 소프트웨어(TEL의 경우 Ingenio가 APC/FDC 상표, TELeMetrics가 원격 모니터링 서비스 — 2015년 기사 기준)가 센서 데이터를 다루고 이 스크립트는 결과 데이터를 다룬다. `--time-col` / `--event-col`로 둘을 같은 시간축에 놓는 것이 결합 지점이며, TEL 내부 구현은 모른다.

## 1. 관리도 종류

| 관리도 | 통계량 | 분모·σ | 용도 |
|---|---|---|---|
| 패턴별 p 관리도 (8종) | 부분군에서 패턴 X로 판정된 비율 | n_i 가 부분군마다 달라도 한계를 n_i 마다 다시 계산: p̄ ± 3·√(p̄(1−p̄)/n_i)·σz | 소모품 마모·챔버 오염 같은 한 방향 추세 |
| 저신뢰 비율 p 관리도 (`LOW_CONFIDENCE`) | confidence < 임계값인 웨이퍼 비율 | 위와 같음 | 분류기가 헷갈리는 웨이퍼가 늘면 새 패턴 출현 또는 분류기 노후 — 모델을 감시하는 관리도. 이것이 오르면 다른 관리도 해석을 보류한다 |
| `FAIL_FRAC_MEAN` I-MR | 부분군의 불량 비율 평균 | σ = baseline 이동 범위 평균 / d2(1.128) | 패턴 없는 '전체 수준' 감시. 세정(CELLESTA / EXPEDIUS) 베이스라인 결함 밀도 감시 같은 용도. 예측 CSV에 `fail_frac` 열이 있을 때만 |

x축은 부분군 번호가 아니라 **웨이퍼 순번**(부분군 끝 웨이퍼)이라 부분군 크기가 패턴마다 달라도 같은 축에 놓인다. 그림에서 음영은 baseline(한계 산출 구간), 세로 점선은 이벤트다.

## 2. 발생률 vs 점유율 — 구성비 문제

예측 CSV에 CLEAN(또는 none) 판정이 있으면 분모가 '검사한 전체 웨이퍼'인 **발생률 관리도**다. 없으면(결함 8종만 있는 `wm811k_evaluate.py` 기본 출력처럼) 분모가 '결함 웨이퍼'인 **점유율 관리도**가 되는데, 점유율은 합이 1이라 한 패턴이 오르면 다른 패턴이 기계적으로 내려간다. 이전 버전의 데모는 점유율 구조였고 EDGE_RING을 올리자 건드리지 않은 CENTER·LOC에 하강 알람 수십 건이 났다. 해결은 셋이다.

1. `chart_mode()`가 CSV에서 어느 쪽인지 자동 판정해 제목·콘솔·보고서에 적는다. 발생률 관리도를 만들려면 `wm811k_evaluate.py --with-none` 출력(y_pred에 CLEAN 포함) 또는 `wm811k_validate.py --export-predictions`처럼 정상 웨이퍼가 들어 있는 예측을 넣는다.
2. 하강 알람은 기본으로 점검 항목에서 뺀다(`--up-only`, 기본 켬, `--no-up-only`로 끔). alarms.csv에는 남기고 `note` 열에 점유율이면 "down: 다른 패턴 상승의 반작용 가능", 발생률이면 "down: 감소 방향 (점검 대상 아님)"을 적는다.
3. 데모는 발생률 시나리오로 바꿨다. CLEAN 약 85%, 결함 8종은 WM-811K 라벨 비율로 나머지 15%를 나누고, 심는 변화는 모두 B 챔버의 CLEAN 웨이퍼를 바꾸는 식이라 다른 패턴의 발생률은 건드리지 않는다.

## 3. 자동 부분군 크기

정규 근사 조건은 n·p̄ ≥ 5 **와** n·(1−p̄) ≥ 5 둘 다다. 패턴마다 baseline 비율 p0로 k = ⌈5 / min(p0, 1−p0) / base⌉를 구해 부분군을 기본 크기(`--subgroup`, 기본 25)의 k배로 키운다. 드문 패턴일수록 부분군이 커지고 그만큼 탐지가 느려진다 — 이것은 설계가 아니라 통계의 대가다. 데모(발생률 기준)에서의 크기:

| 관리도 | baseline p0 | 부분군 | 비고 |
|---|---|---|---|
| LOW_CONFIDENCE | 0.100 | 50 | 가장 빠름 |
| EDGE_RING | 0.0557 | 100 | |
| CENTER / EDGE_LOC | 0.032 / 0.030 | 175 | |
| LOC | 0.019 | 275 | |
| SCRATCH | 0.010 | 500 | 계단 탐지가 약 600장 늦는 이유 |
| DONUT | 0.0067 | 750 | baseline 부분군 4개 |
| RANDOM | 0.005 | 1,000 | baseline 부분군 3개 |
| NEAR_FULL | 0.0003 | 15,000 | baseline 부분군 0개 → 감시하지 않음(사유 출력) |

`--subgroup lot`이면 로트를 쪼개지 않고 연속 로트를 `--min-size`가 될 때까지 합친다(한 로트가 더 크면 그 로트 하나가 부분군). 마지막 조각이 목표의 절반 미만이면 버린다. baseline 부분군이 3개 미만이거나 감시 부분군이 2개 미만이면 그 관리도는 그리지 않고 사유를 '감시하지 않은 관리도'에 적는다.

## 4. Laney p′ 보정

같은 로트의 웨이퍼는 패턴을 공유하므로 로트 간 변동이 이항 분산보다 크다(과산포). 보정 없이 그리면 한계가 너무 좁아 계속 헛울린다. Laney p′는 baseline 부분군의 표준화 점수 z_i = (p_i − p̄)/σ_i 의 **이동 범위 평균 / d2(1.128)** 로 σz를 재서 한계를 σz배 넓힌다.

- **σz 하한 1**: σz < 1(과소산포)이면 1로 고정한다. Laney 원안은 과소산포도 반영해 한계를 좁히지만, 여기서는 이항 한계보다 좁히지 않는다 — 거짓 알람 쪽으로 기울지 않게 하는 의도적 보수화이며 원안과 다르다는 점을 코드 주석에도 적었다.
- **baseline 부분군 < 20이면 생략**: 이동 범위 몇 개로 추정한 σz는 분산이 커서(이전 데모에서 i.i.d. 데이터인데 σz 1.57이 나온 적이 있다) 한계를 엉뚱하게 넓힌다. 생략하면 그림 제목에 `Laney 생략(n_base=k<20)`, 콘솔에 목록을 적는다. 데모에서는 EDGE_RING(n_base 30)·LOW_CONFIDENCE(60)만 보정이 켜졌고 둘 다 σz = 1.00(i.i.d. 합성이라 과산포가 없으니 맞다), 나머지 6개는 생략됐다.
- README의 "실측에서 σz는 1.5~2.8"은 행 순서가 시간이 아닌 WM-811K에서 잰 값이므로 과산포가 아니라 정렬 효과를 포함한다. 실제 팹 데이터에서의 값은 미측정이다.

## 5. 규칙 — Western Electric 4개 + EWMA

| 규칙 | 조건 | 잡는 것 |
|---|---|---|
| R1 | 3σ 밖 1점 | 큰 계단 |
| R2 | 연속 3점 중 2점이 같은 쪽 2σ 밖 | 중간 이동 |
| R3 | 연속 5점 중 4점이 같은 쪽 1σ 밖 | 작은 이동 |
| R4 | 연속 8점이 중심선 같은 쪽 | 아주 작은 이동·드리프트 시작 |
| EWMA | z의 지수가중 이동평균 \|e_i\| > L·√(λ/(2−λ)·(1−(1−λ)^{2i})) | 0.5~1σ의 완만한 드리프트를 3σ 규칙보다 빨리 |

규칙은 창이 완성되는 점에 표시된다(R2는 세 번째 점, R4는 여덟 번째 점). 알람의 방향(`direction`)은 그 점의 z 부호로 정하므로, 상승 창이 하강점에서 완성되는 드문 경우 R3/R4가 `down`으로 기록될 수 있다(케이스 스터디 변형 시퀀스에서 1건 확인; [`roadmap.md`](roadmap.md)).

**EWMA 파라미터**: λ = 0.2, L = 2.86. λ = 0.2에서 ARL0 ≈ 500이 되는 L이 2.86이라는 것은 Lucas & Saccucci(1990) 표 기준이다 — (λ, L) = (0.05, 2.615), (0.10, 2.70), (0.20, 2.86), (0.25, 2.998). 이전 값 2.7은 λ = 0.1의 짝이라 λ = 0.2와 묶으면 ARL0가 500보다 짧았다(허위 알람이 WE 규칙보다 잦음). 표 값은 이 저장소에서 원문으로 재확인하지 않았으므로 '표 기준'으로 적는다. 점근 한계는 L·√(λ/(2−λ)) = 0.953 (z 단위).

## 6. Phase I / Phase II

한계는 앞부분(`--baseline-frac`, 기본 50%)의 안정 구간에서만 잡고 나머지를 감시한다. 전체로 한계를 잡으면 이상이 한계 안으로 흡수된다. baseline 안에서 규칙이 울리면 그 구간이 안정이 아니었다는 뜻이므로 **baseline 알람률**로 따로 보고한다: 안정 공정이면 규칙 5개를 다 켜도 1~2% 수준이고, 5%를 넘으면 "시간 순서가 아니거나 정상 상태가 아니다"라고 경고한다. 데모는 0/147(전체), 0/126(층화)로 0.0%였다.

## 7. 저신뢰 임계값 — 고정값 대신 분위수

`--conf-threshold`를 주지 않으면 baseline 구간 confidence의 하위 분위수(`--conf-quantile`, 기본 0.10)를 임계값으로 쓴다. 모델·클래스 수에 따라 확률 분포가 달라 고정 임계값(예전의 0.7)은 의미가 없기 때문이다. RF 8클래스의 predict_proba 최댓값은 경계 클래스(LOC/EDGE_LOC/SCRATCH)에서 0.4~0.6이 흔할 수 있어 0.7 고정이면 baseline 저신뢰 비율이 수십 %가 될 수 있다(실측 미확인, 추정). 데모의 baseline 분포는 beta(8, 1.2)라 q0.05 0.661 / q0.10 **0.721** / q0.25 0.815 / 중앙값 0.894이고 채택 임계값 0.721이 콘솔과 보고서에 찍힌다. `confidence` 열이 없고 `score` 열이 있으면 score를 별칭으로 쓰되 "규칙 분류기 휴리스틱 점수, 확률 아님"이라고 경고한다.

## 9. 데모 결과 수치 (합성, 로직 확인)

실행: `python wm811k_spc.py --demo` (약 3초) 와 `--demo --group-col chamber --event-col event` (약 3.5초). 시나리오: 6,000장 / 240로트, 웨이퍼 3000부터 40로트에 걸쳐 B 챔버 EDGE_RING 전환 확률 0→0.12(B 발생률 0.057→0.159, 전체 0.057→0.108), 3750부터 B 웨이퍼 30% 저신뢰, 4125부터 B SCRATCH 전환 0.15(B 0.007→0.119, 전체 0.007→0.063), 이벤트 1025 `pm_wet_clean`(A)·2900 `focus_ring_replaced`(B). 시드 3은 시드 0~7을 훑어 고른 값이다(시드 0은 baseline SCRATCH 추정이 0.4%로 낮아 부분군 1,250장·baseline 2개가 되어 감시 불가).

### 9-1. 심은 시점 → 규칙별 첫 탐지 (웨이퍼 순번)

| 관리도 | 심은 시점 | R1 | R2 | R3 | R4 | EWMA | 가장 빠른 규칙 → 지연(장) |
|---|---|---|---|---|---|---|---|
| EDGE_RING (전체) | 3000 (드리프트) | 4099 | 4099 | 3799 | 4299 | 3899 | R3 → +799 |
| EDGE_RING@B (층화) | 3000 | 3974 | 3974 | 3974 | 3574 | 3774 | R4 → +574 (EWMA +774) |
| LOW_CONFIDENCE (전체) | 3750 | 3899 | 3949 | 3849 | 4149 | 3899 | R3 → +99 |
| LOW_CONFIDENCE@B | 3750 | 3874 | 4024 | 4174 | 4774 | 3874 | R1·EWMA → +124 |
| SCRATCH (전체) | 4125 (계단) | 4499 | 4999 | 5999 | − | 4499 | R1·EWMA → +374 |
| SCRATCH@B | 4125 | 4724 | 5674 | − | − | 4724 | R1·EWMA → +599 (부분군 475장) |

읽는 법: 완만한 드리프트(EDGE_RING, 40로트에 걸쳐 +0.10)는 "몇 개 안에" 잡히지 않는다 — 전체 관리도에서는 부분군 8개(R3)·9개(EWMA), 층화하면 2개 더 빠르다(R4 3574는 8점 중 5점이 baseline 끝의 0.06~0.07이라 우연에 기댄 부분이 있고, EWMA 3774가 더 믿을 만한 첫 탐지다). 계단(SCRATCH)은 계단 후 첫 완성 부분군에서 R1·EWMA가 동시에 잡는다. 저신뢰 증가는 부분군이 50~75장이라 가장 빠르다. 층화가 EDGE_RING을 앞당기는 것은 B의 변화가 A에 희석되지 않기 때문이다(전체 중심선 0.0557→최근 0.110, B 0.0573→0.140).

### 9-2. 허위 알람과 비주입 패턴

| 실행 | baseline 알람 | 감시 상승 / 하강 | 심지 않은 관리도의 알람 |
|---|---|---|---|
| `--demo` | 0 / 147 (0.0%) | 276 / 1 (관리도 8, 감시 점 149) | CENTER R4 `down` 1건(5949) — 상승 허위 알람 0 |
| `--group-col chamber --event-col event` | 0 / 126 (0.0%) | 130 / 1 (관리도 11, 감시 점 131) | EDGE_RING@A R1 1건(4399, 값 0.13, z 3.36); LOW_CONFIDENCE@A R1 1건(5799, 0.24, z 3.01); LOC@B R1·R2·EWMA 1점(5974, 0.033, z 3.44, 마지막 부분군 n=300, baseline 부분군 3개뿐); CENTER@B R3 `down` 1건(4874) |

상승 허위 알람은 층화 실행에서 131개 감시 점 중 3점이다. 상승 알람 276/130건이 많아 보이는 것은 심은 변화가 끝까지 이어져 매 부분군마다 여러 규칙이 겹쳐 울리기 때문이다(한 점에 R1~R4·EWMA가 동시에 표시된다). 이벤트 거리 표는 EDGE_RING@B 3574 ← `focus_ring_replaced@2900` +674, SCRATCH@B 4724 ← +1824, LOW_CONFIDENCE@B 3874 ← +974를 낸다. 데모에 심은 이벤트는 드리프트보다 앞에 있어 거리 계산 로직을 보이는 용도이고, "교체 → 복귀"는 [`case_study_8d.md`](case_study_8d.md)의 변형 시퀀스로 보였다.

### 9-3. 그룹 간 발생률 (감시 구간, 카이제곱 p)

## 10. WM-811K 자체에는 못 쓴다

행 순서가 시간이 아니라 제품·로트 블록 순서라, 실측 예측 CSV에 그대로 돌리면 EDGE_RING 비율이 전반부 60%에서 후반부 0%로 떨어지는 식의 계단이 나오고 baseline 알람률이 수십 %가 된다. 스크립트가 이 경우를 진단해 경고한다. WM-811K에는 시각·챔버·슬롯·사이트 정보도 없다. 시각 열이 있는 실제 팹 데이터에 `--time-col`로 쓰는 것이 본래 용도이고, 입력 열은 `lot`, `y_pred`(필수), `confidence`(없으면 `score`), `fail_frac`, 시각·그룹·이벤트 열(선택)이다. 입력을 만드는 것은 `wm811k_evaluate.py`(`wm811k_predictions.csv`, score 열) 또는 `wm811k_validate.py --export-predictions`(`test_predictions.csv`, confidence = RF predict_proba 최댓값)다.

## 11. alarms.csv 열 사전

| 열 | 뜻 |
|---|---|
| `chart` | 관리도 이름. 층화 시 `패턴@그룹` |
| `subgroup` | 그 관리도 안의 부분군 번호(0부터) |
| `wafer_end_idx` | 부분군의 끝 웨이퍼 순번(전역). 그림 x축과 같다 |
| `phase` | `baseline`(한계 산출 구간) / `monitor`(감시 구간). baseline 알람은 "그 구간이 안정이 아니었다"는 신호 |
| `rule` | `R1`~`R4`(Western Electric) / `EWMA` |
| `value` | 부분군 관측값(비율 또는 평균) |
| `z` | (value − 중심선) / σ_i. Laney 보정이 켜지면 σ_i에 σz가 곱해져 있다 |
| `direction` | `up` / `down` — 규칙이 완성된 점의 z 부호 |
| `note` | 하강 알람의 사유: 점유율이면 "다른 패턴 상승의 반작용 가능", 발생률이면 "감소 방향 (점검 대상 아님)". 상승은 빈 칸 |
| `lots` | 부분군에 든 로트명(앞 3개 + …). `--anonymize`면 해시 |
| `acknowledged_at` | (현장 기록용, 빈 칸) 알람을 확인한 시각 |
| `action` | (현장 기록용) 취한 조치 |
| `verified_at` | (현장 기록용) 조치 후 관리도가 중심선으로 복귀한 것을 확인한 시각 |

`subgroups.csv` 열: `chart`, `subgroup`, `n`(부분군 크기), `wafer_end_idx`, `lots`, `value`, `z`, `ewma`, `ewma_limit`, `ucl`, `lcl`, `phase`. 그림을 다시 그리거나 다른 도구(대시보드)에 넣을 때 쓴다.
